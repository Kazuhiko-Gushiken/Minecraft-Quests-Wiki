# Minecraft Quest Wiki

This is the website repository for the Minecraft Quest Wiki. The idea for this website is to present mod information (like a wiki) in a questing format that many people enjoy from playing modpacks. Not only that, but it allows you to signal some sort of progression if you'd like. Sub-chapters are planned to allow splitting larger mods up into different isolated steps, or when a mod has different overall sections, such as Apotheosis with its different modules.

## How to contribute?

In `/mods` you'll find a `chapters.json` file. This defines the chapters. You'll provide it with the following:
- A chapter ID.
- A title.
- A boolean for the sprite sheet and background (as well as default, which is already set).
- The default camera position when someone clicks onto the quest chapter.
- The quest link camera position when someone navigates to a quest via a link.

An example below:
```
[
    {
        "id": "example_mod",
        "title": "Example Mod",
        "spriteSheet": true,
        "background": true,
        "camera": {
            "x": 36,
            "y": 0,
            "zoom": 0.7
        },
        "questLinkCamera": {
            "offsetX": 0,
            "offsetY": 0,
            "zoom": 2
        }
    }
]
```

In `/mods/<mod>` (`<mod>` being the chapter id and mod id (they need to match)) you will have at least one mandatory file, `!quests.json`. This file is where you define quests. You'll supply it with the following:
- Quest ID.
- Quest Title
- Quest Subtitle
- Question Location
- Quest Dependencies/Optional Dependencies/Related Quests
- Index (needed for Icon Sprites)

```
[
    {
        "id": "quest",
        "title": "Quest",
        "subtitle": "The best quest!",
        "location": [2, 0],
        "depends/optionalDepends/related": ["anotherquest", "andanother"],
        "index": 3
    }
]
```

Each quest ID should match it's paired quest description file within the `/mods/<mod>` folder and thus have the same name. As of now, only the Minecraft Legacy Formatting works, so any Markdown formatting, including links, images, tables, emphasis, etc. will not render properly. LaTeX rendering is also a future feature.

The quest dependencies can either be `depends` meaning the line/arrow that connects the two will be a solid color, showing a required dependency. For `optionalDepends`, you'll get a dotted line and arrow to show the progression line, but that quest is optional for the overall mod progression. For `related` it will be a dotted line with no arrow to show relation, but nothing in terms of progression.

In `/mods/<mod>` you may add a background image, one with either of the 4 following extensions:
- .png
- .webp
- .jpg
- .jpeg
It must be named `!background.<ext>`. It will crop in a little to fit the screen, so be aware.

Animated backgrounds will be supported in the future. While the website is hosted in GitHub Pages, only background overlays may be animated (to reduce total bandwidth) though, if a website is hosted externally with a higher bandwidth limit, full image animations may be permitted (must think about those with a slow internet connection as well).

In `/mods/<mod>` you can apply icons to the quests via:
1. `/mods/<mod>/!spritesheet.png`
2. `/mods/<mod>/icons/`
The `icons` directory will house every icon, just so it's available. If the icon will be used, it must be there (this isn't a functional requirement, but an archiving repository requirement). They are to be 64x64 pixels (unless I change something to allow increases to 128x128 as a max) and named by index (starting at 1) to match the index marked by the quest in `!quests.json`.

The sprite sheet will be generated by the `spritesheet.py` script by running it and providing the folder path to the folder with the appropriately named icon files. This will generate a sprite sheet where each sprite takes up 66x66 pixels (1px padding to avoid blending when canvas draws).

Animated sprites will be supported in the future using an automated system to take animated textures (with accompanying `.mcmeta` file) and add them to the sprite sheet with RGBA encoding into the padding, using each channel of the color to signify different things such as:
- Number of Frames
- Framerate
- Flags
- Reserve

Icons for sprites are being obtained with [this mod](https://www.curseforge.com/minecraft/mc-mods/item-icon-exporter) for now, though a custom mod to make life easier will be a future addition (if this wiki idea takes off).

## Formatting

The main formatting method (at the current moment) is Minecraft Legacy Formatting. These can be used in the following locations:
- Chapter Title
- Quest Title
- Quest Subtitle
- Quest Description

Extra formatting can be achieved by the following:
- `\-` For non-breaking hyphens
- `\_` For non-breaking spaces
- `\'` For omissions (or else it may view it as an opening or closing apostrophe)

Double sets of quotes, either from quotes `"` or apostrophes `'` will fail to render properly as the parser isn't set to catch that. Unclosed quotes will be set as an alert when you open the quest.

Write your text with decorations as you normally would. There is no current support for `&k`, obfuscation.

Each new line line in the markdown files will add a natural line break.

## Tips and Requirements

1. Don't go overboard with the coloring and formatting. It's meant to highlight important facts and values without being overwhelming.
2. Don't go overboard with references. In the first quest chapter (Modern Industrialization), I've slotted a few references, but they aren't in every chapter.
3. Keep everything PG... You know, how they did in your favorite kids shows?
4. For the time being, keep explanations relatively simple (given you can get away with it). I plan to add options for a hidden "spoiler" extension that lets you, by default, hide complexities such as mathematical formulas that relate to mod mechanics.
5. Use the same method of icon exporting for the entire quest chapter for consistency, as some mods that export item icons may process them differently.
6. Any sprites that are not within a permissible license, please do ask for permission, take a screenshot, and keep it (or even add it to a PR as `!credits.<ext>` in the mod directory).
